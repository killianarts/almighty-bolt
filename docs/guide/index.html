First principles of high-performance software

Twelve ideas that explain why fast software is built the way it is. Each is shown in the code of a small GUI core, a program that has to produce a new picture every 16.7 milliseconds.

Primary aim. Teach the principles, starting from nothing. They are not about Lisp, macOS or GUIs. A web developer, a game programmer and a database engineer should each recognise them.

Secondary aim. Explain what the core does and how its code works, so that readers can maintain it and train others. Each part of the tour names the principles it shows.

The guide

Each page stands alone and explains the few ideas it needs. Read them in any order. The numbers P1 to P12 are the same everywhere, so a badge such as P6 always leads to the same principle.

Where to start

  • You want the principles. Start at Principles 1. It has what it needs, and the core is only the example. Follow an In the core note into Core 1 or Core 2 when you want the code.
  • You need to read or change the code. Start at Core 1 and go in order. Each part opens with the principles it shows. Open a Principles page when you want the reason for a decision.
  • You are teaching it. Use the trainer's kit.

The twelve at a glance

The first two say what you are optimising for and how you will know. The next three are facts about machines. Five strategies follow, then two about building it.
