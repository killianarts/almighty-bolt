#+TITLE: Benchmark results

One file per run of a script in an app, written by =make bench-run= (the harness of
=bench/results.lisp=). A record is a single s-expression:
=(:almighty-bolt-result 2 :date .. :commit .. :dirty .. :variant .. :app .. :script ..
:machine (..) :repetitions .. :warmups .. :runs (..) :summary (..))=. =:runs= holds the raw
samples of every repetition (the build time of each frame in nanoseconds, the builds it took,
the bytes consed while it was built), =:summary= what they say. The first frame of a run is
cold and is summarized apart; the rest are what the medians and percentiles are of.

A record is never edited. A later run of the same app and script supersedes it, and
=make bench-report= prints the latest of each. What is measured is the ui's build of a
frame, on the real clock, with the real text engine and no window: not the host's waiting for
the display, nor its encoding. The numbers are of the machine in =:machine=; compare records
only from the same machine and treat differences within the spread of the repetitions as ties.

* Modes
Records of version 1 have no =:mode= and are =:headless=. The latest record of each mode, app
and script is what =make bench-report= prints.

- =:headless= (=make bench-run=): the ui's build of a frame, with no renderer.
- =:host= (=make bench-run=): the script played through the host's frame (=run-frame=) into an
  off-screen texture with the real renderer and the instrumentation on. =:columns= names the
  fields of each frame's row in =:runs=; =:summary= is that of =summarize-ring= over the frames
  after the first of each repetition: the frame time and its parts (build with its update,
  layout and paint; the wait for the GPU's frame before; the encoding), the GPU's time, the
  builds in a frame and the share of the build time that was in builds after the first, the
  garbage collected and the bytes consed. There is no window, so no vsync and no wait for a
  drawable. Read the phases of the build (update, layout, paint) and the share of extra builds;
  the wait, the GPU's time and the encoding depend on what state the machine is in and differ
  from one run to the next by a factor of two or three.
- =:overhead= (=make bench-overhead=): what the instrumentation adds to a build, with it off and
  on, in each script and on the null baseline (=bench/null=) through the host. The clock ticks
  in 41.7 ns steps (24 MHz), so a difference of one or two ticks is all that can be seen at
  0.7 us.
- =:app= (=make bench-app=, after =make image=): from outside, for the executable running a
  task in a window: the time from starting it to its first presented frame (=:startup=, the
  first launch and then =:repetitions= - 1 more), the frames drawn, CPU and idle wakeups of ten
  seconds in which nothing happens (after it has drawn nothing for three seconds: =:idle=), the
  resident memory, the peak seen and the heap in use (=:memory=), and the executable's size raw
  and gzipped (=:image=). The first launch after an image is made can be several times slower than
  the rest (the file is not in the system's cache yet). The resident memory after the idle window
  is noisy, because the system compresses the memory of a window that is not used: compare the
  peak and the heap. =:state= is =:idle=, or =:animating= for a task that draws for as long as it
  is open (the dashboard): that one is measured in the ten seconds after its first frame, and
  =:idle= then holds what the animation costs (frames, CPU, wakeups), not an idle floor.
- =:compile= (=make bench-compile=): seconds to compile the library, the 7GUIs models and the
  seven apps from an empty cache, and to compile again after touching one file of the library
  and one of an app.

* Events
The records from commit =49d2d9d= on count the events delivered before each frame. The records
before that are of the frame only, so they leave out the time and bytes of delivering events.

- =:headless=: each repetition in =:runs= has =:event-ns=, =:event-bytes= and =:events=, one for
  each frame (those delivered since the frame before), beside =:build-ns= and =:frame-bytes=,
  which are what they were. =:summary= adds =:event-ns=, =:events-per-frame=, =:with-events-ns=
  (the build and the events together, frame by frame) and =:bytes-per-frame-with-events=.
  =:build-ns= and =:bytes-per-frame= keep their meaning, so the old records can still be read
  beside them.
- =:host=: =:columns= ends with =:events-ns= and =:events= (the time of =handle-event= and the
  number of events since the frame before; the time is in the low 40 bits of the ring's last word
  and the count above). =:summary= adds =:events= (a summary in nanoseconds) and
  =:events-per-frame=. They are counted only while the instrumentation is on.
