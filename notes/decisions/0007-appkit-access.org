#+TITLE: 0007 — How we reach AppKit
#+DATE: 2026-10-24
- Status :: accepted

* Context
[[file:0001-platform.org][0001]] chose native windowing and said AppKit "is reached through the Objective-C
runtime". Writing that down is easy; two ways of doing it exist. cl-nextstep is a
Lisp binding with a C library of Objective-C classes (windows, views, a Metal
view) that the Lisp side drives. Our own bindings would call the Objective-C
runtime from Lisp and make the classes AppKit needs at run time. The first
contradicts 0001's "no extra C dependency", so it was tried before being ruled
out.

* Options
1. cl-nextstep as it is.
2. cl-nextstep, patched or forked (it needed C changes to forward input).
3. Our own bindings, through =sb-alien=, with no C.

* Evidence
Spikes A and B ran the same acceptance script (=spikes/acceptance/=); see the
devlog entries of 2026-10-24 for the numbers.
- Both draw only when asked, answer a request in one display refresh (16.6 ms),
  draw nothing while the window is still, report a resize, receive input, and
  quit when the window closes.
- cl-nextstep's Metal view forwarded no input, and its window forwards only
  closing. Input took a 57-line change to the C source and a rebuild. It
  allocates about 700 bytes a frame, mostly from looking up selectors by string.
- Our bindings (919 lines of Lisp, six files) allocate nothing per message send
  or per callback, receive input and window events as the core's event
  structures, and need no C, no cmake, no dylib and none of cl-nextstep's
  dependencies (cl-opengl among them, and a 4 GB heap to compile them).
- Structures by value work through =sb-alien= on arm64: arguments as flattened
  doubles, results as structures. A Lisp error in a callback is contained.

* Decision
Option 3: our own bindings. cl-nextstep is not adopted. It stays in =vendored/=
only while Spike A is the record of the comparison.

This keeps 0001's "no extra C dependency". It refines 0001's "we own the event
loop": AppKit owns =[NSApp run]=, and the core owns frame scheduling. A paused
=MTKView= with =setNeedsDisplay= draws only when a frame is requested, so frames
happen only on request, as the charter requires. Idle wakeups are measured in
Spike E.

* Consequences
- Easier: no C toolchain or shared library to build and ship; the smallest
  image; every hook AppKit offers (input, resize, scale, focus, and later IME
  and accessibility) is a method of a Lisp-made class, with no C edit per hook;
  message sends and callbacks allocate nothing, which the zero-allocation rule
  needs.
- Harder: we maintain about 900 lines of bindings and the ABI facts under them.
  Only arm64 is verified; on x86-64 a =CGRect= result comes back through
  =objc_msgSend_stret=, which the bindings do not handle. Classes are made by
  hand, with type encodings. The event loop must run on the main thread, so the
  REPL hands work to it (=run-on-main=). A process started from a shell is not
  activated by macOS, so focus events need an app bundle or a terminal of the
  user's own.
- Gives up: cl-nextstep's wider surface (OpenGL views, AVFoundation, WebKit,
  screen capture, widgets), none of which the core needs.
