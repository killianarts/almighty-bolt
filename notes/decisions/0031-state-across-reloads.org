#+TITLE: 0031 — State kept when the app is made again
#+DATE: 2026-10-29
- Status :: proposed

* Context
Record 0030 made the app again whenever code was compiled, and the new app
started from nothing. Micah, 2026-10-29: "Hot restart is not good enough. State
should be kept between reloads."

An app's state is in two places, and they are lost for different reasons.
- The app's own: variables that its constructor closes over (the CRUD's
  entries, the filter, the picked entry), or signals in them. A new call of the
  constructor makes new variables.
- The widgets': what the person did to them (the caret, the selection, the
  scroll, the keyboard focus), and, in the retained variant, everything the app
  keeps in nodes (the text of a field, the items of a list, whether a button is
  enabled), because the app reads it back from there. A new tree is new nodes.

Edits are of two kinds, and a reload must show both: code that makes something
(a label, a width, an initial value) and code that works something out (how an
entry is shown). State that is kept must not hide either.

* Options
1. Keep state where Lisp usually does: in specials or instances that a
   recompile does not touch, with the UI a function called by name. Needs no
   mechanism. No app is written so, and the retained variant cannot be (its tree
   is built once).
2. Record the events and play them into the new app. Needs nothing of the app.
   A recorded click is at a place, so an edit that moves a button sends it
   to the wrong one, and the time grows with the session.
3. Declare the state. The app's own goes in a store that the window keeps; the
   variants carry the widgets' by id.
4. Read the old app's closed-over variables from the closure and put them in the
   new one's. Needs SBCL's internals, a layout that does not change, and every
   closure that shares a variable to be found. Not portable and not reliable.

* Decision
Option 3.
- =kept-let= (core) is =let= for the app's state:
  =(kept-let ((entries (make-entries ...)) (filter "")) body)= binds the
  names as places (symbol macros over cells), so =setf= and closures work as
  with =let=. The window's store keeps the cells by name (the symbol, so two
  apps that name a variable alike do not meet). When the app is made again, a
  name that is in the store gets the cell it had, and its initial form is not
  run. If the initial form is not the one the cell was made from (it was
  edited), the cell is made again, so editing an initial value shows. Cells
  that a pass makes go into the store only if the pass ends without an error.
  Outside a window there is no store and =kept-let= is =let=.
- Only state goes in it: what is worked out (a =computed=, a node) is made
  again from the new code. A name that is dropped keeps its cell, so that
  taking a variable out and putting it back changes nothing. To start over,
  close the window and open it again (=reset-kept-state= clears a store).
  =kept-value= reads a cell, for looking at an app from the REPL.
- The contract gets two generic functions with no-op defaults.
  =inherit-state new old= is called when NEW takes the place of OLD in a
  window, before NEW draws; if it signals, OLD stays and the error is shown.
  =retire-variant= is called on the one that is not used any more, after the
  new one has drawn, or on the new one if its first frame failed. The host
  binds its store while it makes the app again (=reload-host=), and the
  launcher gives the first make the same one.
- Immediate: the new variant takes the old one's UI (focus, the state of each
  widget by key, input not yet read); what was laid out and painted is
  dropped, in case it is the library that was edited.
- Retained: nodes are matched by id (a node without one by its parent's key and
  its place) and type. The nodes hold what the app reads back, so a state slot
  of the old tree that differs from what it was when the tree was made
  (=snapshot-node=) is carried, and one that does not is left as the new code
  made it: an edited label shows, a typed field stays. The focus and whether
  the keyboard was already offered to a canvas are carried. This is done only
  for an app that uses =kept-let=; any other is started again, because the
  nodes would otherwise show what its variables do not have (found with the
  Counter). =make-retained-variant ... :after-reload fn= calls the app's own
  function that brings the view in line with the model, for what the app works
  out from code that may have changed (how an entry is shown).
- Reactive: the signals are kept with =kept-let=, and what a node shows comes
  from them when the screen is described, so the widgets carry only what a
  signal does not hold: the caret and selection of a field with the same text,
  the scroll of a list, the focus. The old tree is unmounted when retired.
- 7GUIs: the CRUD of the three variants uses it; the other tasks do not yet
  and start again when reloaded.

* Evidence
- Tests: =kept= (16), the host's =inherit-state= and =retire-variant= order (8),
  the three variants' carry (immediate 5, retained 25, reactive 6), the CRUD in
  every variant driven with and without a reload in the middle and ending in
  the same place (6 acceptance tests, 30 assertions). All new code was
  mutation-checked: 41 defects, each caught.
- A mutation run is only as good as the compiled file it runs. ASDF takes a
  compiled file for current unless the source is newer by a second, and a
  source put back from a copy is older than the compiled file of its mutant,
  so ten of the retained mutations ran against an earlier mutant and said what
  it said. The harness now deletes the compiled file before and after each
  run, and those were run again.
- A real window, the real tree, a saved CRUD file (make 7guis HOT=1), each
  variant: a person added, a filter typed, the keyboard left in the name
  field after "Zed!". After the save (0.52 to 0.79 s) the entries, the field
  that has the keyboard and its caret are as they were, and the next key goes
  in at the caret.
- The same from Micah's Slynk, started as Sly starts it, with C-c C-c on the
  retained =make-crud= with a label given an id: the new label is there, the
  entries, the keyboard and the caret are kept, and typing goes on.
- The Counter of the retained variant, not given =kept-let=, showed 1 after a
  reload while its variable was 0, when widget state was carried for every app.
- The CRUD of the retained variant does not need the =:after-reload= for any
  of the tests that drive it; it is needed when the code that shows an entry
  is edited, and a test that redefines =entry-display= fails without it.

* Consequences
- Easier: edit, compile or save, and the open window changes with the app's
  state, the widgets' state, the keyboard and the caret where they were.
- The app must say what its state is. Three CRUD files changed: =kept-let= for
  =let= and an import (immediate 77 to 79 lines of code, reactive 90 to 92,
  retained 98 to 101), and the reactive and retained ones are indented one
  level more because a =let*= or a =let= of what is worked out or built now
  sits inside it. These are measured files.
- Not equal across the variants, and that is evidence and not a ranking.
  Immediate: the app's variables are all of its state, and the library carries
  one object. Reactive: the signals are the state and the nodes are rebuilt
  from them. Retained: state is in the nodes and in the app's variables, so it
  needed the most in the library (a list of state slots for each widget, a
  snapshot of the tree, a matching of nodes) and a function in the app.
- Harder: a variable that is renamed starts again; an edited initial form
  resets its variable (by design); an app that keeps nothing restarts, and its
  retained nodes do not carry either.
- Harder: a =defstruct= that is changed leaves the old instances in the store
  as Lisp leaves them anywhere.
- The reactive variant leaves the =computed= values of the old app subscribed
  to the signals it shares with the new one (they are marked stale and told
  nothing else). The elements of the old app are let go of.
- A window that is opened and closed leaves its NSWindow behind (0030).
- Not done: the other 7GUIs tasks and the stress apps, which restart; the
  reference page does not yet describe =kept-let=, =open-app= and =close-app=.
